# Technical Debt

Debt generally refers to technical debt, as a whole.

Technical debt represents the extra development work that arises when code is written in a quick-and-dirty way instead of following best practices. Previous work has left issues to be fixed later and that later is now.

Technical debt is not built visibly on the spot, but is usually assessed later, when the need for a previous chore becomes a reality. It may be opposed to ``YAGNI``: ``you are not going to need it``.

There are many types of debt: code, maintenance, documentation, readable, visual, etc.

By extension, anything that currently slows down development is considered a debt.
